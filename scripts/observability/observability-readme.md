# Observability Scripts

Operational helpers for monitoring and managing the thesis-infra MLOps stack.
These scripts are intended for human operators (not automated by Ansible at
runtime) and provide quick visibility into system health, port-forward tunnel
state, and model-version consistency.

## Contents

| Script | Purpose |
|---|---|
| `port-forward-all.sh` | Manage `kubectl port-forward` tunnels for all UI services |
| `healthcheck.sh` | Six-layer system health verification (infra / storage / resources / ports / services / model) |

---

## 1. `port-forward-all.sh`

Starts, stops, restarts, or inspects `kubectl port-forward` tunnels for every
service exposed for local access. UIs accessible after starting:

| Local Port | Service | Notes |
|---|---|---|
| 8000 | FastAPI inference endpoint | model serving |
| 5000 | MLflow tracking UI | experiment registry |
| 9000 | MinIO S3 API | object storage (S3-compatible) |
| 9001 | MinIO Console | web UI for buckets |
| 8080 | Kubeflow Pipelines UI | KFP runs/experiments |
| 3000 | Grafana | dashboards |
| 9090 | Prometheus | metrics + queries |
| 9093 | Alertmanager | alert routing |
| 8889 | Jupyter Lab | notebook IDE (SSH tunnel, not kubectl) |

> The script is **auto-generated by Ansible** from
> `files/scripts/port-forward-all.sh.j2` during Playbook 00. Do not edit it
> directly — modify the template instead.

### Usage

```bash
# Start all tunnels (idempotent — skips already-running ones)
./scripts/observability/port-forward-all.sh start

# Stop all kubectl tunnels (Jupyter is left alone)
./scripts/observability/port-forward-all.sh stop

# Full restart (stop + start)
./scripts/observability/port-forward-all.sh restart

# Show currently-active tunnels + their PIDs and uptime
./scripts/observability/port-forward-all.sh status
```

### Behavior notes

- **Idempotent**: if a tunnel is already listening on the expected port, the
  script reports `OK` and does not respawn it. Useful after restarting a single
  service without disturbing the others.
- **Orphan-safe**: when a service's pod is restarted (`kubectl rollout restart`),
  the corresponding tunnel becomes stale. Run `restart` after any pod restart
  to refresh the affected tunnel.
- **Logs**: each tunnel writes to `/tmp/pf-<svc>.log`. If a tunnel fails to
  bind, the last two lines of its log are printed.
- **SSH-only services**: Jupyter Lab (port 8889) is a systemd-managed service
  on the VM itself, reached over SSH local-forwarding. It is **not** managed by
  this script — the script only reports whether it is listening.

### Typical workflow after `kubectl rollout restart`

```bash
# After restarting any deployment, refresh tunnels
./scripts/observability/port-forward-all.sh restart

# Then verify
./scripts/observability/healthcheck.sh ports
```

## 2. `healthcheck.sh`

Comprehensive, six-layer system health check. Each layer is independently
runnable, and the script exits with a non-zero status if any check fails —
suitable for CI smoke tests and pre-experiment validation.

### Six layers

| # | Layer | What it verifies |
|---|---|---|
| 1 | **infra** | Node `Ready`; pod counts per namespace; all PVCs `Bound` |
| 2 | **storage** | MinIO buckets present (`thesis-data`, `thesis-mlflow`, `thesis-models`); PostgreSQL databases (`mlflow`, `kfp`) accessible |
| 3 | **resources** | Node CPU% / MEMORY% from `kubectl top nodes` (warns at 70%, fails at 85%) |
| 4 | **ports** | Each expected port-forward tunnel is listening on `localhost` |
| 5 | **services** | Each service responds to its HTTP `/health` (or equivalent) endpoint — 2xx healthy, 3xx redirect (alive), 401/403 auth-protected (alive), 5xx/timeout = fail |
| 6 | **model** | FastAPI loaded model version == MLflow `@production` alias == drift baseline on disk == drift baseline in cluster ConfigMap |

### Usage

```bash
# Full report (all six layers)
./scripts/observability/healthcheck.sh

# Run a single layer
./scripts/observability/healthcheck.sh infra
./scripts/observability/healthcheck.sh storage
./scripts/observability/healthcheck.sh resources
./scripts/observability/healthcheck.sh ports
./scripts/observability/healthcheck.sh services
./scripts/observability/healthcheck.sh model

# CI / scripting mode — suppress output, return exit code only
./scripts/observability/healthcheck.sh --quiet
echo "Exit: $?"   # 0 = all passed, 1 = at least one failure

# Help
./scripts/observability/healthcheck.sh --help
```

### Exit codes

| Code | Meaning |
|---|---|
| `0` | All checks passed |
| `1` | One or more checks failed |
| `2` | Invalid usage (unknown layer name or bad flag) |

### What each `FAIL` typically means

| Failure | Most likely cause | Recovery |
|---|---|---|
| Node not Ready | k3s service down | `systemctl restart k3s` |
| `ns/<name>` pods not ready | a deployment is failing | `kubectl describe pod -n <ns> <pod>` |
| PVC not Bound | storage provisioner misconfigured | check k3s local-path provisioner |
| MinIO buckets missing | Playbook 04 has not completed | `ansible-playbook playbooks/04-minio.yml` |
| PostgreSQL databases missing | Playbook 05 has not completed | `ansible-playbook playbooks/05-postgres.yml` |
| Node memory > 85% | workload overload | restart heavy pods, check OOMKilled events |
| Port not listening | tunnel orphaned by pod restart | `./scripts/observability/port-forward-all.sh restart` |
| Service HTTP fail | tunnel up but pod down, or wrong endpoint | `kubectl logs -n <ns> <pod>` |
| Model version mismatch | retraining promoted a new version but downstream not refreshed | `ansible-playbook playbooks/12-evidently.yml --ask-vault-pass` |

### When to run it

| Situation | Command |
|---|---|
| Daily morning smoke test | `./scripts/observability/healthcheck.sh` |
| Before starting Notebook 04 (drift experiment) | `./scripts/observability/healthcheck.sh model` |
| After running an Ansible playbook | `./scripts/observability/healthcheck.sh infra` |
| After `kubectl rollout restart` | `./scripts/observability/healthcheck.sh ports services` |
| In CI / pre-experiment gate | `./scripts/observability/healthcheck.sh --quiet` |
| Debugging an unreachable UI | `./scripts/observability/healthcheck.sh ports` then `services` |

## Pre-experiment checklist

Before running Notebook 04 (drift simulation + recovery latency measurement),
run this sequence:

```bash
# 1. Refresh all tunnels (cleans orphans from earlier sessions)
./scripts/observability/port-forward-all.sh restart

# 2. Wait 5 seconds for tunnels to bind
sleep 5

# 3. Full health check — must report all OK
./scripts/observability/healthcheck.sh

# 4. If any layer reports FAIL, fix it before proceeding.
```

If `model` layer reports a version mismatch (e.g., baseline lags behind MLflow
`@production`), regenerate the baseline:

```bash
ansible-playbook playbooks/12-evidently.yml --ask-vault-pass
./scripts/observability/healthcheck.sh model
```

## Design notes

### Why two scripts instead of one

`port-forward-all.sh` is a **stateful action** (starts/stops processes);
`healthcheck.sh` is a **stateless observation** (reads but never modifies).
Mixing them would conflate verbs (act vs report) and make CI usage harder —
a health check that occasionally restarts tunnels would be non-idempotent and
violate the principle of least surprise.

### Auth-aware liveness in `services` layer

The HTTP check is **status-code-based**, not body-content-based:

- `2xx` — healthy (body grep applied if pattern configured)
- `3xx` — redirect, alive (e.g., Jupyter token redirect)
- `401` / `403` — auth-protected, alive (e.g., MinIO S3 API root)
- `4xx` (other) / `5xx` / `000` (timeout) — fail

This handles services that are running and accessible but require
authentication for the root endpoint, which is the common production case.

### Idempotency

Both scripts are safe to re-run any number of times. `port-forward-all.sh`
checks each port before spawning; `healthcheck.sh` makes no state changes.

### Logging

`port-forward-all.sh` writes per-service tunnel logs to `/tmp/pf-<svc>.log`,
useful when a tunnel fails to bind (the script prints the last two lines on
failure). `healthcheck.sh` writes nothing to disk; all output is to stdout.
